Laravel + React Native : brancher un frontend mobile sur une API REST

Comment faire dialoguer une API Laravel et une app React Native sans s'emmêler les pinceaux : CORS, tokens, gestion d'erreur et pièges classiques.

Quand j'ai commencé à travailler sur UNFLOW (une app React Native), j'ai vite eu besoin d'un backend. J'ai choisi Laravel, parce que c'est la stack que je connais le mieux côté serveur. La première fois qu'on met les deux en regard, on tombe sur trois problèmes bêtes qui vous font perdre une après-midi. Voici lesquels et comment les court-circuiter.

Problème 1 : le CORS qui bloque tout

Symptôme : votre app React Native appelle http://localhost:8000/api/..., et vous obtenez une erreur réseau incompréhensible. Le fetch ne renvoie rien. Vous soupçonnez un bug dans le téléphone. C'est en réalité CORS — Laravel bloque les requêtes venant d'une autre origine par défaut.

Solution : dans Laravel, installez le package officiel fruitcake/laravel-cors (ou utilisez le middleware CORS natif depuis Laravel 10+), et configurez config/cors.php :

'paths' => ['api/*'],
'allowed_methods' => ['*'],
'allowed_origins' => ['*'],
'allowed_headers' => ['*'],
'supports_credentials' => true,

En développement, '*' suffira. En production, remplacez par l'origine exacte de votre app.

Problème 2 : localhost ne marche pas depuis un téléphone

C'est le piège que tout le monde rencontre une fois. Votre téléphone n'a pas accès à localhost de votre PC, parce que pour lui, localhost, c'est lui-même. Solution : utilisez l'IP locale de votre machine sur le réseau Wi-Fi :

const API_URL = __DEV__
  ? 'http://192.168.1.42:8000/api'
  : 'https://api.monsite.com';

Pour trouver l'IP : ipconfig sur Windows, ifconfig sur macOS/Linux. Le téléphone et le PC doivent être sur le même réseau. Et n'oubliez pas de lancer Laravel avec php artisan serve --host=0.0.0.0 pour qu'il accepte les connexions externes.

Problème 3 : l'authentification

Le scénario classique : votre app doit authentifier un utilisateur. Trois options s'offrent à vous :

  • Sanctum (recommandé pour une app mobile) : tokens par utilisateur, stockés côté mobile.
  • JWT : tokens signés, sans état côté serveur. Plus standard, mais plus de plomberie.
  • Session + cookies : déconseillé pour du mobile, conçu pour du web.

Pour UNFLOW, j'ai utilisé Sanctum. La création d'un token se résume à :

// routes/api.php
Route::post('/login', function (Request $request) {
    $user = User::where('email', $request->email)->first();
    if (!Hash::check($request->password, $user->password)) {
        return response()->json(['message' => 'Invalid credentials'], 401);
    }
    $token = $user->createToken('mobile-app')->plainTextToken;
    return response()->json(['token' => $token]);
});

Côté React Native, stockez le token avec expo-secure-store (pas AsyncStorage — les tokens en clair dans AsyncStorage sont une faille). Puis envoyez-le en header :

fetch(API_URL + '/me', {
  headers: { Authorization: 'Bearer ' + token }
});

Gérer les erreurs proprement

Le réflexe du débutant : attraper le 200 et ignorer le reste. En production mobile, ce qui compte, c'est ce qui se passe quand le réseau coupe, quand le serveur renvoie 500, quand le token expire. Voici le wrapper que j'utilise :

async function apiCall(path, options = {}) {
  const res = await fetch(API_URL + path, {
    ...options,
    headers: {
      'Content-Type': 'application/json',
      Authorization: token ? 'Bearer ' + token : '',
      ...options.headers,
    },
  });
  if (res.status === 401) {
    // rediriger vers login
  }
  if (!res.ok) {
    const error = await res.json().catch(() => ({}));
    throw new Error(error.message || 'Erreur réseau');
  }
  return res.json();
}

Une fonction, et toutes vos routes passent par là. Vous centralisez la gestion d'erreur, le header d'auth, et le parse JSON. Trois sources de bugs en moins.

Le détail qui fait la différence : loading et refreshing

Vos utilisateurs n'attendent pas seulement que les données arrivent ; ils veulent voir que ça charge. Sur une FlatList, utilisez refreshing sur le RefreshControl. Sur les écrans, un ActivityIndicator quand loading est true. Ça paraît bête, mais c'est ce qui sépare une app qui fait pro d'une app qui fait étudiante.

En résumé

Laravel + React Native, c'est une stack très saine une fois qu'on a passé les trois écueils : CORS, localhost, et auth. Tout le reste, c'est de la discipline : un wrapper de fetch, des états de chargement explicites, et une gestion d'erreur centralisée. Pas de magie — juste de la méthode.
